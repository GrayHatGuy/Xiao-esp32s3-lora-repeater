# v8.3.1 — Radio 2 module-revision (V1.0 / V1.1) variants + bring-up hardening

Porting / change record for the v8.3.1 patch. Purpose: document exactly what
changed and how to fold it into the other dual-SX1262 branches (primarily
`dev-ABP-lorawan`, also `T_LORA_QUAD*`, `lr1121-phase1`).

Authored on branch `v8.3.1-r2-pin-variants` off `main` (= v8.3 + post-ship docs).

---

## 1. Root cause (one paragraph)

Seeed ships the **"Wio-SX1262 for XIAO" edge module (Radio 2) with two different
pinouts**. The chip-select (NSS) is on **D4 / GPIO5** on **V1.0** but **D3 / GPIO4**
on **V1.1**. The v8.x firmware only ever shipped the V1.0 map. On a **V1.1** module
that map drives the wrong GPIO as NSS, so the module's *real* chip-select (GPIO4)
is never parked — and `busyWait(R2)` actively reconfigures it to a floating
`INPUT`. The un-deselected V1.1 chip then drives the **shared MISO** during Radio
1's `begin()`, corrupting the version read → `[Radio1-B2B] begin() failed: -2`
(`CHIP_NOT_FOUND`) → FATAL halt (Radio 1 is mandatory). This is the same
floating-CS-on-shared-MISO failure already documented in commit `db98740` /
`V8.2-SPEC.md` A2 — here triggered by a module-revision pin mismatch instead of a
disabled slot. Boards with a V1.0 module are unaffected, which is why it
reproduced on one bench and not another with "identical" hardware.

## 2. The two pin maps

XIAO ESP32-S3 edge pins: `D0=GPIO1 D1=GPIO2 D2=GPIO3 D3=GPIO4 D4=GPIO5 D5=GPIO6`.
The module's right-hand silkscreen column sockets onto `D0..D6` top→bottom.

| Signal | **V1.0** (silkscreen `D0,DIO1,RST,BUSY,NSS,RF_SW,D6`) | **V1.1** (silkscreen `DIO1,BUSY,RST,NSS,RF_SW,D5,D6`) |
|--------|----|----|
| DIO1   | D1 / **GPIO2** | D0 / **GPIO1** |
| BUSY   | D3 / **GPIO4** | D1 / **GPIO2** |
| RST    | D2 / **GPIO3** | D2 / **GPIO3** (same on both) |
| NSS    | D4 / **GPIO5** | D3 / **GPIO4** |
| RF_SW  | D5 / **GPIO6** | D4 / **GPIO5** |

- `RST` is **GPIO3 on both revisions** — this is what makes the bring-up hardening
  (hold R2 in reset) work regardless of which variant is flashed.
- The V1.1 map (`NSS=4 DIO1=1 RST=3 BUSY=2 RF_SW=5`) is the silkscreen-correct map
  and is **bench-confirmed on a physical V1.1 module**. (Note: an earlier
  hand-tuned map `RST=2/BUSY=6` *also booted*, but had no real hardware reset and
  no BUSY handshake — do **not** use it; ship the silkscreen map.)

## 3. Changes made (4 files)

### `src/main.cpp`
1. **R2 pin block** → revision selector. `#ifndef WIO_SX1262_REV` (default `10` =
   V1.0; `11` = V1.1) wrapping two `#ifndef`-guarded pin blocks, plus
   `WIO_SX1262_REV_STR` (`"V1.0"`/`"V1.1"`). Each `R2_*` stays overridable by a
   single `-DR2_NSS=..` flag. **Radio 1 and the SPI bus pins are left as plain
   `#define`s — R1 is fixed B2B silicon, never remapped.**
2. **Boot echo** (after the CS-park): `Serial.printf("[diag] R2 edge module = %s
   (NSS=%d DIO1=%d RST=%d BUSY=%d RF_SW=%d)\n", WIO_SX1262_REV_STR, ...)`.
3. **Bring-up hardening** (3 edits in `setup()`):
   - After constructing the radios, assert R2 in hardware reset:
     `if (g_radioEnabled[1]) { pinMode(R2_RESET, OUTPUT); digitalWrite(R2_RESET, LOW); }`
   - Run `busyWait(R1_RESET, R1_BUSY, "R1")` only — **remove the pre-loop
     `busyWait(R2_…)`** (it floats R2's real CS during R1.begin()).
   - Replace the unified begin loop with explicit phases: R1 first (still fatal if
     it fails — but now R2 is held off the bus, so an R1 failure is genuinely R1);
     then **release R2** with `busyWait(R2_RESET, R2_BUSY, "R2 release")` and
     `g_radio[1]->begin()`, with a **non-fatal** self-diagnosing message on failure
     that names the silkscreen check and the env to flash.

### `platformio.ini`
New env `[env:xiao_esp32s3_v1_1]` — references `${env:xiao_esp32s3.build_flags}`
once and appends `-DWIO_SX1262_REV=11` (no `extends`, per the existing bench-env
warning). The base `[env:xiao_esp32s3]` is unchanged (= V1.0 default).

### `README.md`

## 4. Behavior / do-no-harm

- **V1.0 board, default env:** functionally identical. The *only* change is serial
  log ordering — the R2 reset diag now prints `[diag] R2 release  BUSY after
  reset = …` **after** `[Radio1-B2B] ready` (R2 is reset after R1). Flash stays
  24.6%.
- **V1.1 board, `xiao_esp32s3_v1_1`:** both radios detect; boot echo reads
  `= V1.1 (NSS=4 DIO1=1 RST=3 BUSY=2 RF_SW=5)`.
- **Wrong variant (either direction):** R1 comes up; R2 fails non-fatally → single
  radio + the diagnostic message. **No more FATAL halt.**

## 6. Porting to `dev-ABP-lorawan` (and other dual-SX1262 branches)

The bring-up region (pin defines + `setup()` radio init) is **byte-identical** to
v8.3 on `dev-ABP-lorawan` (audit-verified; `src/WioSX1262.{cpp,h}` are identical
too). The ABP work lives in **disjoint** regions (`main.cpp` ~lines 30/365/577/637
+ a `LoRaWANCrypto::selfTest()` call ~line 1262, plus `src/LoRaWANCrypto.h` and the
`[env:bench_lw_enc]` env). **No textual conflict with the bring-up edits.**

Recommended path:
1. Land/commit the patch on `v8.3.1-r2-pin-variants` first; finalize the `v8.3.1`
   tag on `main`.
2. `git checkout dev-ABP-lorawan && git cherry-pick <v8.3.1 commit(s)>`. Expect
   **line-offset fuzz only** (the branch is ~+128 lines offset in the bring-up
   region); no semantic conflict.
3. If a hunk rejects, re-apply manually — the four edits match on code *text*, not
   line numbers, so they apply cleanly against the identical bring-up source. On
   the branch the regions are roughly: R2 pin defines ~109-113, CS-park ~1374-1382,
   `busyWait` ~1398-1414, begin loop ~1449-1460.
4. **Do not duplicate** the existing NSS-only CS-park block — the hardening edit
   *extends* it (adds the R2-reset hold). The branch already carries that block.
5. `platformio.ini`: add the `xiao_esp32s3_v1_1` env (place near the existing
   `bench_lw_enc` hunk; same `${...}`-once pattern). README/CHANGELOG port as-is.
6. Rebuild both envs on the branch (`pio run -e xiao_esp32s3` and
   `-e xiao_esp32s3_v1_1`) to confirm green before pushing.

Same recipe applies to `T_LORA_QUAD*` / `lr1121-phase1` if/when they need V1.1
support; those branches add radios beyond the 2-SX1262 base but share the R2 edge
bring-up.
