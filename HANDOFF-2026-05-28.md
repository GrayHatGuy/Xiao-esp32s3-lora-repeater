## 2. Sub-GHz RX bring-up — what's been tried (all FAILED)

All tests below configured Radio 2 (Wio-LR1121) for **MC public at 910.525 MHz / BW62.5 / SF7 / sync 0x12**. Radio 1 (SX1262) in the same hardware receives normally; LR1121 receives at most one spurious packet at boot, then nothing.

### Hardware-side checks — all passed ✅

- VDD 3.27 V steady at module pads 20/21, no brown-out
- End-to-end DMM continuity on every signal (SCK, MOSI, MISO, NSS, RST, BUSY, DIO9)
- Antenna verified on SUBG_RF pad 23 (915 MHz antenna, not the 2.4G IPEX pad 2)
- Swap to a fresh LR1121 module on a different carrier — identical symptom
- Swap to a known-good Xiao ESP32-S3 — identical symptom
- Logic analyzer SPI capture confirms SCK/MOSI/MISO carry correct LR11x0 protocol bytes
- Chip detection works: `Found LR11x0: 0x03 Base FW version: 1.3`
- BUSY-poll bring-up confirms chip releases BUSY at ~141 ms post-reset

### Firmware-side hypotheses — all exhausted

**RFSWx DIO brute-force sweep** (`-DLR1121_BRUTEFORCE_RX_DIOMASK=N`, see platformio.ini lines 34-65):
- 5-bit mask covering all candidate chip RFSWx outputs:
  - bit 0 → DIO5 (RFSW0)
  - bit 1 → DIO6 (RFSW1)
  - bit 2 → DIO7 (RFSW2)
  - bit 3 → DIO8 (RFSW3)
  - bit 4 → DIO10 (RFSW4 — freed because Wio-LR1121 has integrated TCXO, no 32k crystal)
- Sweep results: **values 0..7, 8, 16, 24, 25, 31 all failed identically** (no real RX, only post-TX spurious empty reads). Completed 2026-05-26. See `LR1121-SPEC.md` "Brute-force MODE_RX DIO sweep — RESULTS".

**DOE-style RX-init audit** (`-DLR1121_RX_AUDIT_RUN=N`, see platformio.ini lines 67-117):
- **Run 0** — Baseline + `getErrors()` diagnostic — chip errors reported clean, confirmed self-echo pattern at known RSSI
- **Run 1** — Pre-`standby(STBY_RC)` before `setRfSwitchTable` (per LR1121 UM v2.2 §4.2.1: SetDioAsRfSwitch returns CMD_FAIL outside STBY_RC; RadioLib discards the return) — **no change**
- **Run 2** — `setRssiCalibration` with UM Table 7-21 "600 MHz to 2 GHz" reference tunes (top candidate: chip ships calibrated for LR1121 EVK matching network, not Wio-LR1121's) — **no change**
- **Run 3** — Explicit `calibrateImageRejection(902, 928)` for US sub-GHz ISM (UM §2.1.3: POR image-cal fails on chips with TCXO fitted; Wio-LR1121 has integrated TCXO) — **no change**
- **Run 4** — `setRxBoostedGainMode(true)` — **no change** (expected ~2 dB; not the issue)
- **Run 5** — Kitchen-sink combination of Runs 1+2+3+4 — **no change**
- **Run 6** — "Meshtastic-style" stack mirroring stock Meshtastic firmware's working LR1121 path on LilyGO T3S3:
  - Switch table declares only DIO5 + DIO6 (DIO7/8/10 = NC)
  - `setRegulatorDCDC()` after `begin()` (RadioLib defaults to LDO)
  - `setPreambleLength()` before every `startReceive()` (Meshtastic's undocumented "Solve RX ack fail" workaround)
  - `setRxBoostedGainMode` stays OFF
- **Run 8** (2026-05-28, AUDIT_RUN=6 mode) — Meshtastic-style stack on top of Seeed-authoritative locked switch table — **both treatments confirmed inert**

**Full audit details:** see `LR1121-RX-INIT-AUDIT.md` in the repo root.

### Diagnostic signature (what the failure looks like in serial)

ISR-instrumented heartbeat reveals:
- ISR fires only on **TX_DONE** events (every R2 transmit → +1 ISR)
- ISR **never fires on RX_DONE** for real OTA traffic
- All read() calls return `pktLen=0, state=0, len=0` (empty reads after spurious IRQ)
- R1 (SX1262) in same hardware receives 10+ packets in same time window

**Definitive root signal:** the Wio-LR1121's DIO9 IRQ asserts on TX events but not on RX_DONE for incoming packets — and no combination of RadioLib API calls (setRfSwitchTable, setDioIrqParams, setRegMode, image cal, RSSI cal, preamble, boosted RX) changes this.

### Conclusion

**All firmware-side hypotheses are exhausted.** Application firmware is *paused pending Seeed engineering reply* on the Wio-LR1121's authoritative RF switch wiring / RX path config. The full bench-test trail is documented in `LR1121-RX-INIT-AUDIT.md` and `LR1121-SPEC.md` for Seeed support to review.

## 3. 2.4 GHz band testing — STATUS: NOT YET PERFORMED

**This is the critical gap and the highest-value next workstream.**

### What's been done on 2.4 GHz

- ✅ **Architecture is in place** for 2.4 GHz config:
  - `BridgeConfig` chip-aware frequency validation already accepts **2400–2500 MHz** for LR1121 radios
  - 13 dBm TX-power ceiling on the 2.4 GHz band (region-exempt) wired into `handleSave()`
  - `RegionPreset.h` has wideLora modem-preset variants (812.5 / 406.25 / 1625 kHz BWs)
  - `slotFrequency2G4()` and `bandCenter2G4()` helpers for Meshtastic 2.4 GHz channel-slot computation
  - `WioLR1121::begin()` uses RadioLib 7.x `LR1121::begin(freq, bw, sf, cr, syncWord, power, preambleLength, tcxoVoltage)` which accepts 2400-2500 MHz directly

- ✅ **Antenna hardware:** the 2.4 GHz IPEX antenna connector is on the **Wio-LR1121 module pad 2 (`2.4G RF`)** — that pad is already exposed, just needs a 2.4 GHz antenna plugged in (the user has a 915 MHz antenna currently on the SUBG_RF / pad 23 connector).

### What's NOT been done on 2.4 GHz

- ❌ **No hardware bring-up.** Radio 2 has never been configured for a 2.4 GHz frequency.
- ❌ **No 2.4 GHz antenna installed.** The IPEX MH4 connector for pad 2 exists; no antenna is plugged into it.
- ❌ **No Meshtastic 2.4 GHz peer device used in any test.** All testing has been against MC devices in the sub-GHz US ISM band.
- ❌ **All audit runs and brute-force sweeps were sub-GHz only.** None of the RFSWx values tested correspond to 2.4 GHz signal paths — those use *different* DIO pin routings per the LR1121 user manual.

### Why 2.4 GHz might "just work" where sub-GHz failed

The LR1121's 2.4 GHz signal path uses a **different on-chip RF block** than the sub-GHz path:

- Different LNA (the 2.4 GHz "HF" path vs the sub-GHz "LF" path)
- Different RF switch routing (the chip has dedicated 2.4 GHz switch outputs separate from the sub-GHz ones)
- Different image calibration band (already handled by RadioLib for >1 GHz)
- Different default TX power ceiling (13 dBm vs 22 dBm — Phase 1 already enforces this)

**If our sub-GHz silence is caused by a Wio-LR1121-specific RX-path bug on the sub-GHz side** (e.g., wrong LNA enable, switch table doesn't match Seeed's actual board schematic for the sub-GHz RF block), **the 2.4 GHz path could be completely unaffected**, because the chip routes 2.4 GHz through entirely separate hardware on the silicon.

In other words: a 2.4 GHz test would either:
1. **Work cleanly** → bypasses the sub-GHz issue, gives the project its headline cross-band demo, and Phase 1 ships as "sub-GHz known-limitation, 2.4 GHz functional"
2. **Fail the same way** → confirms a Wio-LR1121-module-level RX issue affecting both bands, which strongly suggests a hardware defect in the module that Seeed needs to address

Either outcome is high-value information.

## 6. Operational gotchas the new session needs to know

- **Phase 0 dual-SX1262 path is regression-clean** and must stay that way. The `RADIO_PROFILE_DUAL_SX1262` build profile preserves the original size profile. Don't break SX126x in pursuit of LR11x0 fixes.
- **NVS schema v5 auto-migrates from v4** in place. Don't `pio run -t erase` between tests unless you want to lose the portal config.
- **Portal re-entry trigger:** within 5 s of reset, press BOOT or send any serial char.
- **`platformio.ini` lib_deps must contain `jgromes/RadioLib @ 7.7.0`** — earlier sessions accidentally deleted this line when reformatting; if RadioLib.h "not found", check this first.
- **Hot-swapping the B2B SX1262 shield is forbidden** — power off, swap, power on.
- **LR1121 antenna pads are not interchangeable:** pad 2 = 2.4 GHz only, pad 23 = sub-GHz only. The chip routes through entirely separate internal RF blocks.
