# Core1121 — WaveShare Core1121 (LR1121) as Radio 2

**Branch:** `CORE1121` (off `lr1121-phase1`).
**Status:** wired and benched. R2 boots/TX/reads-EUI healthy, but is **RX-deaf at the
MeshCore BW62.5 config** — bench-confirmed RX center **>30 kHz LOW** (a frequency offset, not
BW/sync). Root cause grounded (TCXO/XOSC calibration) and a flag-gated fix (`CORE1121_TCXO_RECAL`)
+ a Serial mutex are implemented (both compile; **uncommitted, unverified on HW**). **The live
investigation, root-cause analysis, and the owner-run A/B procedure are in [`CLAUDE.md`](CLAUDE.md) §0
(esp. §0.10).**
**Background / baseline:** the full Wio-LR1121 investigation lives on the
[`lr1121-phase1`](https://github.com/GrayHatGuy/Xiao-esp32s3-lora-repeater/tree/lr1121-phase1)
branch — keep it intact until the RX-deficit question (below) is resolved.

---

## 1. What this is

Radio 2 of the XIAO ESP32-S3 dual-LoRa bridge changes from the **Seeed Wio-LR1121**
to the **WaveShare Core1121** — *same Semtech LR1121 chip, different board*. Radio 1
(Seeed Wio-SX1262, sub-GHz) is unchanged. Everything else about the bridge
(protocols, captive portal, FreeRTOS dual-radio architecture) is unchanged — see
[`README.md`](README.md).

## 2. Why — board-vs-chip control

On the `lr1121-phase1` branch the Seeed Wio-LR1121 showed a **marginal sub-GHz RX
deficit**: alive and in continuous RX, detects every preamble, but completes only a
small, unreliable fraction of packets — even strong ones. R1 (SX1262), same board
and config, receives everything. Every firmware-side remedy was exhausted (full DOE
on `lr1121-phase1`), so the open question is **board vs chip**:

- **Core1121 receives cleanly** (completes packets the Seeed R2 drops, identical
  conditions) → it's a **Seeed board design flaw** → the Core1121 is the path forward.
- **Core1121 shows the same deficit** → it's **LR1121 chip/firmware level** → affects
  any LR1121; escalate.

The decisive advantage: **WaveShare publishes a full schematic** (`Core1121_XF_Sch.pdf`),
so this board's RF wiring is known exactly — unlike the Seeed module, whose RF-switch
wiring had to be obtained from Seeed support.

## 3. What changed (firmware)

- **New driver** [`src/Core1121.cpp`](src/Core1121.cpp) / [`.h`](src/Core1121.h),
  wired into `makeRadio()`; the Seeed `WioLR1121.*` driver was retired on this branch.
- **RF-switch table** = the schematic-verified **pSemi PE4259 SPDT** truth table:
  `STBY{0,0} RX{1,0} TX{0,1} TX_HP{0,1} TX_HF{0,0}`, driven by **DIO5 + DIO6** only.
  Only `MODE_TX` differs from the Seeed **SKY13373 SP3T** (`{1,1}`→`{0,1}`), because
  the PE4259 has a single TX throw. Full derivation:
  [`docs/datasheets/waveshare/CORE1121-RF-SWITCH.md`](docs/datasheets/waveshare/CORE1121-RF-SWITCH.md).
- **Removed the Seeed-only bring-up scaffolding** (the `LR1121_BRUTEFORCE_RX_DIOMASK`
  DIO sweep and the `LR1121_RX_AUDIT_RUN` 0–6 DOE — both existed only to hunt the
  Seeed module's undocumented wiring / RX deficit). **Kept** the still-useful
  instruments: chip-EUI boot logging, `debugIrqStatus()` / IRQ heartbeat, `LR1121_DEBUG`.
- **TCXO** = 3.0 V (confirmed correct for the Core1121).
- **`R2_RX_ONLY_TEST` is OFF** → normal R1↔R2 bridging is active.

## 4. Board facts (Core1121-XF, schematic-derived)

- **RF switch:** pSemi **PE4259** SPDT on the sub-GHz path, complementary-pin control
  via **DIO5** (RFSW0_V1) + **DIO6** (RFSW1_V2). Only the **HP PA** output is wired
  (R3 = 0 Ω; R4 = NC).
- **2.4 GHz** uses `RFIO_HF` → a **separate antenna (ANT1)**, bypassing the PE4259.
  Sub-GHz uses **ANT2** (LORA_ANT) behind the switch.
- **TCXO** 32 MHz @ 3.0 V; **32.768 kHz crystal** on **DIO10/DIO11** → those DIOs stay
  `RADIOLIB_NC` (must not be driven as RF-switch outputs).
- **DIO9 = IRQ** (RX_DONE), wired to XIAO GPIO2.
- References: [`Core1121_XF_Sch.pdf`](docs/datasheets/waveshare/Core1121_XF_Sch.pdf),
  [`CORE1121-RF-SWITCH.md`](docs/datasheets/waveshare/CORE1121-RF-SWITCH.md),
  [`docs/REFERENCES.md`](docs/REFERENCES.md).

## 5. Wiring (Core1121 → XIAO ESP32-S3)

The Core1121 is a separate module (16-pin header + two IPEX antenna ports), so it is
**hand-wired** to the XIAO edge pins the old R2 slot used. SPI is shared with R1; only
the chip-select differs. No `ANT_SW` wire — the PE4259 is driven internally by the LR1121.

| XIAO pin | GPIO | → Core1121 (U3 pin) | Signal |
|---|---|---|---|
| D4  | 5 | NSS (14)    | SPI chip-select |
| D1  | 2 | DIO9 (3)    | IRQ / RX-done |
| D2  | 3 | NRESET (10) | reset |
| D3  | 4 | BUSY (9)    | busy |
| D8  | 7 | SCK (13)    | SPI clock *(shared)* |
| D10 | 9 | MOSI (12)   | SPI MOSI *(shared)* |
| D9  | 8 | MISO (11)   | SPI MISO *(shared)* |
| 3V3 | — | 3V3 (8)     | power |
| GND | — | GND (2/7/15)| ground |

Sub-GHz antenna on **ANT2**; add the 2.4 GHz antenna on **ANT1** when using 2.4 GHz.

## 6. Bring-up plan / status

1. Wire per §5; flash the current build (R1↔R2 bridging is enabled).
2. At boot, capture the **chip EUI** line (`[Radio2-Edge] chip EUI = …`) to identify
   the physical module in the logs.
3. Run the **same RX comparison** the Seeed module ran, side-by-side: the safe OTA
   distance-sweep method on `lr1121-phase1`
   ([`docs/testbed/RX-DEFICIT-MEASUREMENT.md`](https://github.com/GrayHatGuy/Xiao-esp32s3-lora-repeater/blob/lr1121-phase1/docs/testbed/RX-DEFICIT-MEASUREMENT.md)).
   Compare R2 completion-rate vs R1, against the Seeed baseline.
4. **Verdict:** Seeed-board-flaw vs LR1121-chip-level.

Status: wired and benched; the board-vs-chip verdict is **pending the RX-offset fix** — see the
RX-deaf-at-narrow-BW investigation in [`CLAUDE.md`](CLAUDE.md) §0 (root cause grounded in §0.10; the
`CORE1121_TCXO_RECAL` A/B that decides Seeed-board-flaw vs LR1121-chip-level is owner-run on the bench).
`pio run -e xiao_esp32s3` passes (baseline and with `-DCORE1121_TCXO_RECAL`).

## 7. Rules of engagement (carried from the project)

- **Don't guess** — cite the datasheet/schematic/code for electrical/timing/safety/
  RF-switch claims; say "I don't know" otherwise. Reverts and "no-op" conclusions need
  the same citation.
- **One variable per experiment.** No mid-experiment edits that contaminate the record.
- **No RF-switch / PA / timing changes without written, datasheet/schematic-cited rationale.**
- **Never cable a high-power source into an RX front end** (LR1121 abs-max +10 dBm).
- **Owner reviews all outbound** (Seeed, PRs) — drafts only. **Pseudonym (`GrayHatGuy`)
  in docs; never the real name. Never force-push `main`.**
